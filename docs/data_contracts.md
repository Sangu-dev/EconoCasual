## 1. Raw Observational Retail Data (`data/mock_retail.csv`)

This is the primary input schema expected by the frontend ingestion engine (`UploadPage.jsx`) and the backend upload endpoint (`POST /api/upload`). It represents observational historical transactions where discounts were applied under potential confounding.

| Column Name | Data Type | Constraint / Domain | Required | Description |
| :--- | :---: | :---: | :---: | :--- |
| `customer_id` | string / int | Unique identifier | **Yes** | Primary key representing an individual shopper |
| `age` | int | $18 \le \text{age} \le 80$ | **Yes** | Customer age in years |
| `loyalty_score` | float | $0.0 \le s \le 1.0$ | **Yes** | Engagement index based on tenure and app activity |
| `past_orders` | int | $\ge 0$ | **Yes** | Historical lifetime purchase count |
| `avg_order_value`| float | $> 0.0$ | **Yes** | Historical mean transaction basket size (\$USD) |
| `discount` | int | $\{0, 1\}$ | **Yes** | Binary treatment indicator (`1` = discount applied, `0` = control) |
| `revenue` | float | $\ge 0.0$ | **Yes** | Observed transaction revenue (\$USD) |

> **Schema Validation Rule:** The browser PapaParse engine verifies all 7 columns upon upload. If any column is missing or misspelled, a diagnostic alert banner will highlight missing fields.

## 2. Causal Effect Scores (`data/ite_scores.csv` / `frontend/public/mock_ite.json`)

Output generated by the Double Machine Learning pipeline (Role A) predicting the Individual Treatment Effect for each customer record.

| Column Name | Data Type | Constraint / Domain | Required | Description |
| :--- | :---: | :---: | :---: | :--- |
| `customer_id` | string / int | Unique identifier | **Yes** | Foreign key linking to customer record |
| `ite` | float | Real number ($-\infty, +\infty$) | **Yes** | Estimated incremental revenue lift ($\Delta \text{Revenue}$) from discount |
| `age` | int | $18 \le \text{age} \le 80$ | **Yes** | Customer age |
| `loyalty_score` | float | $0.0 \le s \le 1.0$ | **Yes** | Customer loyalty index |
| `avg_order_value`| float | $> 0.0$ | **Yes** | Historical average basket size (\$USD) |
| `past_orders` | int | $\ge 0$ | Optional | Historical lifetime purchase count |

## 3. Uplift Evaluation Coordinates (`data/uplift_curve.csv`)

Coordinate series for rendering cumulative Uplift and Qini benchmark curves. Compares model targeting performance against the theoretical Oracle ceiling and the uniform random baseline.

| Column Name | Data Type | Constraint / Domain | Required | Description |
| :--- | :---: | :---: | :---: | :--- |
| `fraction_targeted` | float | $0.0 \rightarrow 1.0$ (monotonic) | **Yes** | Cumulative fraction of total customer population targeted |
| `model_gain` | float | Non-decreasing trajectory | **Yes** | Cumulative revenue lift using DML ITE ranking |
| `oracle_gain` | float | Upper bound trajectory | **Yes** | Theoretical maximum lift using true ground-truth treatment ranking |
| `random_gain` | float | Linear diagonal baseline | **Yes** | Expected cumulative lift under uniform random targeting |

## 4. Budget Allocation Recommendations (`data/allocation.csv`)

Customer-level recommendations produced by the constrained optimization engine (Role B) under a specified marketing budget limit.

| Column Name | Data Type | Constraint / Domain | Required | Description |
| :--- | :---: | :---: | :---: | :--- |
| `customer_id` | string / int | Unique identifier | **Yes** | Foreign key linking to customer record |
| `discount_amount` | float | $\ge 0.0$ | **Yes** | Recommended promotional discount dollar value (\$USD) |
| `expected_gain` | float | Real number | **Yes** | Projected net incremental revenue gain (\$USD) |
| `segment` | string | Categorical | **Yes** | Causal behavioral segment (`Persuadables`, `Sure Things`, `Lost Causes`, `Sleeping Dogs`) |

---

## 5. Strategy Comparison Benchmarks (`data/strategy_comparison.csv`)

Aggregate policy evaluation metrics comparing total marketing expenditure and total incremental revenue across different targeting paradigms.

| Column Name | Data Type | Permitted Values | Required | Description |
| :--- | :---: | :---: | :---: | :--- |
| `strategy` | string | `blanket`, `random`, `optimized` | **Yes** | Name of promotional allocation policy |
| `total_spend` | float | $\ge 0.0$ | **Yes** | Total campaign promotional budget expended (\$USD) |
| `total_gain` | float | $\ge 0.0$ | **Yes** | Total cumulative incremental revenue generated (\$USD) |

## 6. Pre-Packaged Demo & Verification Datasets

All datasets are bundled under `frontend/public/` for offline testing and local evaluation:
- **`sample_retail.csv` (1,000 rows):** Valid observational retail dataset for standard feature verification.
- **`synthetic_10k.csv` (10,000 rows):** High-volume scale dataset for WebGL rendering and latency SLA validation.
- **`invalid_sample.csv`:** Malformed dataset missing `discount` and `revenue` to verify client-side error handling.
- **`mock_ite.json`:** Pre-computed customer ITE records for instant offline dashboard hydration.
